# gk-assets

Blender-authored game assets and the tooling to build them. Nothing in this
repo ships in a game build — no gameplay logic, no engine integration, no
runtime code.

- **Working rules:** [AGENTS.md](AGENTS.md)
- **VFX pipeline, read before authoring:** [vfx/README.md](vfx/README.md)

## First five minutes

```bash
pip install -r requirements.txt   # numpy + Pillow
python tools/doctor.py            # is this checkout ready?
python tools/build.py             # build everything, then verify
python tools/serve.py             # preview at the URL it prints
```

`doctor.py` exits non-zero if something blocks a build. Run it before reading a
traceback — the failures it covers (no Blender, a dead MCP bridge, a missing pip
package) all produce confusing errors further down.

## The one command that matters

```bash
python tools/build.py                       # all five sub-programs
python tools/build.py shield_fire_idle      # just one
python tools/build.py --skip-verify         # discouraged
```

It always runs the same three steps in this order, and the order matters:

1. **build** — render per-layer sequences and previews
2. **pack** — sequences → sprite sheets, refresh `vfx/index.json`
3. **verify** — assert the sheets and composites are actually correct

Step 3 is not optional decoration. A build script can exit 0 and produce a
solid rounded rectangle where fire should be; that is a real failure this repo
produced, and only the verifier catches it. `build.py` also ignores Blender's
exit code alone, because Blender exits 0 even when it cannot open a script.

## Layout

```
tools/            scripts (see below)
vfx/              VFX sub-programs, one directory per effect
  index.json       list of effect ids (regenerated by pack_sheets)
  <id>/
    effect.json    MANIFEST — single source of truth for the viewer
    <id>.blend     the scene
    textures/      source textures this effect owns, if any
    sheets/        packed sprite sheets   ← the deliverable, committed
    sequences/     per-frame renders      ← regenerable, ignored
    preview/       flat composite frames  ← review only, ignored
    README.md      the brief: layers, timing, measured values, known issues
render/           RESERVED for full-frame and video-still output
video/            RESERVED for a video generator
```

`render/` and `video/` are empty placeholders. Do not add structure to them
speculatively — put a working tool there first.

## Completeness: what is a machine's call and what is yours

**Built and verified** — `verify_all.py` passes. This means the sub-program has
correct shape, size, colour, frame count, no collapsed frames, and a closed
loop. **That is finished work.** `python tools/review.py --list` reports it as
`done`, and nothing in the build or verification path consults review state.

**Human sign-off** — someone looked at it in the viewer and recorded a
judgement. This is *optional extra assurance*, not a gate. No sub-program is
blocked without one.

The two states are tracked separately only so they are never confused. A
sign-off becomes **invalid** when the effect is rebuilt — that is a real
inconsistency, and both tools report it as `STALE` with a non-zero exit.

### One command to review

```bash
python tools/review_ui.py
```

Serves the viewer with a review overlay and opens your browser. Each
sub-program carries a badge — `done`, `done · reviewed by <name>`,
`done · sign-off stale`, `verify FAIL`, or `not built`. Pick one, type your
name and what you saw, press Approve or Reject.

Useful flags: `--port 8099`, `--no-open`, and `--list` to just print the
state without starting a server.

A sign-off needs **both** a reviewer and an observation. The Approve and Reject
buttons stay disabled until both are filled, and the server rejects the request
with 400 if either is missing — so an agent filling this in through the browser
cannot produce a bare approval either.

`review.py` is the CLI equivalent, and both write the same
`vfx/<id>/review.json`:

```bash
python tools/review.py --list
python tools/review.py shield_ice_idle --approve --by "your name" --note "what you saw"
```

**Agents must not approve.** An agent can prove a sprite is the right shape and
colour, but cannot tell you whether it reads as a shield in motion. That
judgement stays human.

## Adding a sub-program

1. `vfx/<id>/effect.json` — copy an existing one. It is the only place layout,
   blend mode, layer notes and known issues live.
2. `tools/<name>.py` — `import shield_rig`, compose layers. Use a per-card
   material when a layer animates independently; a shared material cannot give
   two cards different keyframed values.
3. Register it in `EFFECTS` in `tools/build.py`.
4. `python tools/build.py <id>`
5. `vfx/<id>/README.md` — layers, frame timing, measured values, known issues.

## Running Blender

Two installs exist on this machine and **they render differently**, so a sheet
rendered on one is not byte-identical to the other. Never hardcode a path:

```bash
python tools/blender_path.py           # resolved binary
python tools/blender_path.py --all     # every install + MCP add-on status
```

The resolver prefers the install that has the official Blender Lab **MCP
add-on** (5.1 on `D:`), because that is the one reachable from a live GUI
session, and falls back to the LTS install (5.2 on `C:`). To call it directly:

```bash
BLENDER=$(python tools/blender_path.py)
"$BLENDER" --background --factory-startup --python tools/shield_idle.py
```

### When MCP says "cannot connect"

The MCP **server** starting proves nothing — it starts fine and only fails per
call, because it is a bridge to a socket *inside* Blender. Check the bridge:

```powershell
Get-NetTCPConnection -LocalPort 9876
```

Nothing listening means the server is fine and the bridge is dead: start
**MCP Bridge Server** from Blender's MCP preferences and tick **Auto Start**.
Restarting Blender without that breaks it, and the error message points at the
wrong layer. `doctor.py` reports this as a `warn`.

## Working checkout and source assets

Blender art is authored directly in the repository checkout, on the branch
selected by the owner. Do not create a separate worktree for an art-only task
unless the owner asks. Before rendering, check that Blender's active
`bpy.data.filepath` points into this checkout; save the current scene here if it
does not.

Keep reusable objects and source textures under `assets/`, or an effect's
`textures/` directory, and use repo-relative Blender links (`//...`). A packed
texture does not replace its source file in the repository.

An authoring scene may drive several effect packages — a lifecycle rig is
authored once and exported into per-effect scenes.

## Verification

`verify_all.py` checks each sub-program from the **rendered sheets**, not the
build code. Sheets are the committed deliverable, so a fresh clone can be
verified without running a build first — which is deliberate: a checker that
only works immediately after a build is not much of a check.

It asserts: manifest/grid agreement, that no layer's frames collapsed to
duplicates, that composited frames meet saturation / fill / silhouette-raggedness
/ aspect gates, and that looping effects have no empty frame and close their
loop.

Compositing the layers during verification mirrors what the game does at
runtime, so it tests the shipped artefact rather than a full-resolution preview.

**The gates are calibrated at sheet resolution, not preview resolution.** The
4× downsample that produces a sheet genuinely lowers measured saturation, so a
threshold tuned on a 512px preview flags correct fire as washed out. Measured
across all five shipped effects:

| Gate | Shipped range | Threshold | Catches |
|---|---|---|---|
| saturation (α-weighted R−B) | 0.15 – 0.36 | **< 0.12 fails** | desaturated / white-clipped |
| white fraction | 0 – 0.013 | **> 0.10 fails** | blown-out core |
| fill ratio | 0.011 – 0.365 | **> 0.62 fails** (lower is advisory) | solid rectangle (~1.0) |
| silhouette raggedness | 0.46 – 0.94 | **< 0.18 fails** | smooth disc (~0.02) |
| bbox height / width | 0.44 – 0.90 | **< 0.40 fails** | flat band, not a dome |

Two things worth knowing if you retune these:

- **Saturation is α-weighted, not α-masked.** Masking averages every pixel
  above a 0.05 floor; a sparse effect is mostly faint pixels whose dark
  accumulated colour drags the mean down. That reported a correct sheet as
  0.12 when the same frame measured 0.45 in the preview.
- **Fill's lower bound is advisory.** A thin effect legitimately covers little
  of its cell; only a near-solid frame is a defect, whichever way it fails.

It samples at frames where each effect is *whole*. A one-shot's tail is
legitimately sparse — `shield_fire_break` at frame 19 is a scatter of falling
cinders with no dome, and demanding a full barrier there would fail a correct
effect. Each effect declares its own sample points in `SAMPLE_AT`.

`test_flame_card.py` does the same for a single card, which is the fastest way
to iterate on a shader without ring composition confusing the read.

## Conventions

**Resolution** — author at 512px, deliver at 128px via `pack_sheets.py --scale`.
At 128 a card is ~20–30px, so detail is sub-pixel and averages to a flat block.
The game's `actor-hud-elements` icon art is 128px, so that is the gameplay cell.

**Colour** — render with `view_transform = "Standard"`. Blender's default AgX
is a filmic look that desaturates; orange effects come out cream.

**Emission strength must stay ≤ 1.0.** A sprite render writes shader RGB
straight to the file, so anything above 1.0 clips every channel to white and
destroys the hue ramp. Brightness comes from the colour ramp and from scale.

**Alpha masks are driven by distance, not angle.** A radial mask must be
`black at large distance → white at centre`. Getting the polarity backwards,
plus the ColorRamp's Fac clamp, turns the whole card opaque.

**Rotate cards only if the mask is rotation-invariant.** UV-space masks rotate
with the card, so an animated rotation drags the silhouette off-centre. Get
"life" from the animated 4D noise `W` instead.

**Blend modes** — `additive` for energy (flash, sparks, embers), `normal` for
smoke so it can occlude. Additive over the bright lawn washes out to white.

**Sheets are committed; `sequences/` and `preview/` are not.** Sheets are what
the game loads. The other two are build output and would add ~68 MB.

## Known traps

Each of these shipped a visibly wrong render before measurement caught it.
`vfx/README.md` has the full list with the numbers behind each.

- `render_sequence` must call `scene.frame_set(frame)`; `write_still` renders
  the *current* frame, so without it every output is identical.
- `ShaderNodeMath` MULTIPLY_ADD silently falls back to defaults; spell constants
  as explicit MULTIPLY then ADD/SUBTRACT so a wrong value is visible.
- A `VectorMath` SUBTRACT with a `default_value` set **and** a link on the same
  socket uses the link and drops the default — producing a sheared field (a hard
  diagonal seam) instead of a disc.
- A ColorRamp Fac takes a SCALAR. Feeding it the raw UV vector makes Blender
  average x and y, giving a diagonal gradient, not a vertical one.
- Multiplying several EASE ramps gives a smooth gradient, not fire. Use one hard
  threshold on the noise.
- `wipe()` must remove suffixed leftovers; a plain select-all/delete leaves
  `SF_Flame_00.001` objects accumulating as invisible geometry.
- Sheets are packed top-down; tiles are pasted without flipping.
- Blender exits 0 even when it cannot open a `--python` script.

## Engine target

The browser preview is **Phaser 4**, the same engine the web game runs
(`web/fusion-rpg-web`, phaser 4.2.1). Previewing in the real engine means a
sheet that reads correctly here will read correctly in game.

This repo is not the web workspace, so there is no relative path to a Phaser
build. `serve.py` resolves one from a candidate list and serves it at a virtual
`/__phaser/` route, which the viewer's import map points at. An import map is
parsed before any page script runs, so the substitution has to be server-side;
the page probes the route first and shows a legible error instead of a blank
stage.

The in-game Unity VFX layer (`VfxDirector`, `docs/architecture/vfx-ssot.md` in
the game repo) is a **separate** system, spec-locked to generated textures with
no asset pipeline. Sheets from this repo are not for it.

Game-side integration is **not** done. The Phaser wiring, additive blend
convention and occupant-container parenting are specified in `vfx/README.md`
but unimplemented.
