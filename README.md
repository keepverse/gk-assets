# gk-assets

Blender-authored game assets and the tooling to build them. Nothing in this
repo ships in a game build — no gameplay logic, no engine integration, no
runtime code.

- **Working rules:** [AGENTS.md](AGENTS.md)
- **VFX pipeline (read before authoring):** [vfx/README.md](vfx/README.md)

## Layout

```
tools/            scripts. blender_path.py resolves a Blender; the rest are
                  build / pack / verify / preview entry points.
vfx/              VFX sub-programs, one directory per effect
  index.json       list of effect ids (regenerated by pack_sheets)
  <id>/
    effect.json    MANIFEST - single source of truth for the viewer
    <id>.blend     the scene
    textures/      source textures this effect owns, if any
    sheets/        packed sprite sheets   <- the deliverable, committed
    sequences/     per-frame renders      <- regenerable, ignored
    preview/       flat composite frames  <- review only, ignored
    README.md      the brief
render/           RESERVED for full-frame and video-still output
video/            RESERVED for a video generator
```

`render/` and `video/` are empty placeholders. Do not add structure to them
speculatively — put a working tool there first.

## Working checkout and source assets

Blender art is authored directly in the repository checkout and the branch
selected by the owner. Do not create a separate worktree for an art-only task
unless the owner explicitly asks for one. Before rendering, check that
Blender's active `bpy.data.filepath` points into this checkout; save the
current scene here if it does not.

Keep reusable objects and source textures under `assets/`, or an effect's
`textures/` directory, and use repo-relative Blender links (`//...`).
Generated textures, references, render frames, sheets and previews stay under
`vfx/` with their source scenes. A packed texture does not replace its source
file in the repository.

An authoring scene may drive several effect packages — a lifecycle rig is
authored once and exported into per-effect scenes.

## Running Blender

Two installs exist on this machine and they render differently, so never
hardcode a path:

```bash
python tools/blender_path.py           # resolved binary
python tools/blender_path.py --all     # every install + MCP add-on status
```

The resolver prefers the install that has the official Blender Lab **MCP
add-on** (5.1 on `D:`), because that is the one reachable from a live GUI
session, and falls back to the LTS install (5.2 on `C:`).

To drive Blender over MCP the add-on's socket server must be running *inside*
Blender. If tools report "cannot connect", the server is usually fine and the
**bridge** is dead:

```powershell
Get-NetTCPConnection -LocalPort 9876
```

Nothing listening means start the MCP Bridge Server from Blender's MCP
preferences and tick Auto Start — restarting Blender without that breaks it,
and the error message points at the wrong layer.

## Workflow

1. **Author** in `tools/<id>.py`, importing `shield_rig`.
2. **Build.** `"$BLENDER" --background --factory-startup --python tools/<id>.py`
   Renders transparent per-layer RGBA sequences at 512px.
3. **Pack.** `python tools/pack_sheets.py --write-index`
4. **Verify.** `"$BLENDER" --background --factory-startup --python tools/verify_all.py`
5. **Preview.** `python tools/serve.py` then open the printed URL.

## Verification

`verify_all.py` checks every effect from the *rendered output*, not the build
code: manifest/grid agreement, that no sheet's frames collapsed to duplicates,
that composites meet saturation / fill / silhouette-raggedness / aspect criteria
at frames where the effect is intact, and that looping effects have no empty
frame and close their loop.

`test_flame_card.py` does the same for a single card (the fastest way to
iterate on a shader without ring composition confusing the read),
`test_shield.py` for one composite, and `test_viewer.py` boots the browser
preview and asserts an effect actually renders.

A script that exits 0 while producing garbage is the failure mode these exist
to catch, so do not skip them.

## Conventions

**Resolution** — author at 512px, deliver at 128px via `pack_sheets.py --scale`.
At 128 a card is ~20-30px, so detail is sub-pixel and averages to a flat block.
The game's `actor-hud-elements` icon art is 128px, so that is the gameplay cell.

**Colour** — render with `view_transform = "Standard"`. Blender's default AgX
is a filmic look that desaturates; orange effects come out cream.

**Emission strength must stay ≤ 1.0.** A sprite render writes shader RGB
straight to the file, so any strength above 1.0 clips every channel to white
and destroys the hue ramp. Brightness comes from the colour ramp and scale.

**Alpha masks are driven by distance, not angle.** A radial mask must be
`black at large distance -> white at centre`. Getting the polarity backwards,
plus the ColorRamp's Fac clamp, turns the whole card opaque.

**Rotate cards only if the mask is rotation-invariant.** UV-space masks rotate
with the card, so an animated rotation drags the silhouette off-centre. Get
"life" from the animated 4D noise W instead.

**Blend modes** — `additive` for energy (flash, sparks, embers), `normal` for
smoke so it can occlude. Additive over the bright lawn washes out to white.

## Known traps

- `render_sequence` must call `scene.frame_set(frame)`. `write_still=True`
  renders the *current* frame, so without it every output is identical.
- `ShaderNodeMath` MULTIPLY_ADD silently falls back to defaults; spell
  constants as explicit MULTIPLY then ADD/SUBTRACT so a wrong value is visible.
- A `VectorMath` SUBTRACT with a `default_value` set **and** a link on the same
  socket uses the link and drops the default — producing a sheared field (a hard
  diagonal seam) instead of a disc.
- A ColorRamp Fac takes a SCALAR. Feeding it the raw UV vector makes Blender
  average x and y, which is a diagonal gradient, not a vertical one.
- Sheets are packed top-down. Tiles are pasted without flipping; a vertical
  mirror here is easy to miss.
- `wipe()` must remove suffixed leftovers. A plain select-all/delete leaves
  auto-suffixed objects (`SF_Flame_00.001`) that accumulate as invisible
  geometry inside the good ones.

`vfx/README.md` has the full list with the measurements behind each.

## Engine target

The browser preview is **Phaser 4**, the same engine the web game runs
(`web/fusion-rpg-web`, phaser 4.2.1). Previewing in the real engine means a
sheet that reads correctly here will read correctly in game. The viewer resolves
a Phaser build through a virtual route served by `tools/serve.py`, so this repo
does not need its own copy of the engine.

The in-game Unity VFX layer (`VfxDirector`, `docs/architecture/vfx-ssot.md` in
the game repo) is a **separate** system, spec-locked to generated textures with
no asset pipeline. Sheets from this repo are not for it.
